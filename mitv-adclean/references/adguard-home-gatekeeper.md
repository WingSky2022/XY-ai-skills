# AdGuard Home 家庭广告门卫（监控 + 拦截常驻方案）

> 来源：2026-10-25 小米电视贴片治理评估沉淀。电视端 DNS 过滤（公共 AdGuard DNS）已拦截小米自家广告族，但无法拦截爱奇艺 cupid 贴片族——公共 DNS 不接受自定义清单，需自建。本文是自建方案的可执行版。

## 定位

局域网内一台**常开设备**（树莓派 / NAS / 软路由 / 小主机，任选其一，功能等价）运行 AdGuard Home，充当全屋过滤 DNS。

```text
阶段一 监控（头几天）：只记日志不拦 → 把贴片嫌疑人实锤成完整域名清单
阶段二 门卫（从此长期）：持续拦截 + 上游广告库自动更新 + 查询日志发现漏网新域
```

**必须常驻的原因**：DNS 是实时问答。设备每次拉广告前都问一次域名，门卫必须当场回答「查无此域」。撤岗 = 设备断网（DNS 悬空）或广告复活（改回公共 DNS）。门卫是滤芯，不是一次性扫地机器人。

## 已预定位的拦截清单（起点，非全量）

- `api.cupid.ptqy.gitv.tv`、`t7z.cupid.ptqy.gitv.tv`（爱奇艺贴片族，2026-10-25 实测在公共 AdGuard DNS 下未拦截、解析真实 IP）
- 社区补充清单：https://github.com/liamliu108/miTVhosts（剔除 xmpush 推送族、market 商店族、hpplay 投屏族、api.io.mi.com 米家族——按用户取舍保留功能）
- 监控期查询日志补齐剩余。

## 部署步骤（一晚完成）

1. 设备入网：插电接路由器 LAN，查内网 IP，路由器上做 DHCP 地址保留。
2. 安装（Docker）：
   ```sh
   docker run -d --name adguardhome --restart always \
     -p 53:53/udp -p 53:53/tcp -p 3000:3000 \
     -v /opt/adguardhome/conf:/opt/adguardhome/conf \
     -v /opt/adguardhome/work:/opt/adguardhome/work \
     adguard/adguardhome
   ```
3. 初始化：浏览器开 `http://<设备IP>:3000` 走向导；设管理账号；DNS 监听 `0.0.0.0:53`。
4. 上游 DNS：`223.5.5.5`、`119.29.29.29`（国内低延迟）；开启「常规设置 → 拦截清单」的 AdGuard 官方清单自动更新。
5. 监控期：电视/设备 DNS 指向门卫 IP，先不拦截只看查询日志（日志默认开启），正常使用几天。
6. 拦截期：把监控确认的广告域加进「过滤器 → 自定义过滤规则」（`||api.cupid.ptqy.gitv.tv^` 语法），验证贴片消失且正片/投屏/推送正常。
7. 固化：路由器 DHCP 把 DNS 下发为门卫 IP（全家自动）；或逐设备手动。

## 电视端接入注意（对接本技能 Phase 5）

- 电视改法同 Phase 5：网络设置切「静态 IP」模式，DNS1 = 门卫 IP。DHCP 模式下填会被覆盖。
- 门卫验证：电视上 `ping ad.xiaomi.com` 应 127.0.0.1；`ping www.mi.com` 正常。

## 成本、维护与边界

| 项 | 口径 |
|---|---|
| 硬件成本 | 树莓派 ¥100-300；功耗约 3W，年电费约 ¥10 |
| 维护循环 | 上游清单自动更新；偶看日志 → 新广告域 → 规则加一行 |
| DoH 趋势 | 部分新 App 用加密 DNS 绕过局域网门卫（电视端目前少，长期风险） |
| 同 CDN 广告 | 广告素材与正片同域名时无法分离，拦不了（诚实边界） |
| 门卫宕机 | 全家「联网但打不开」；应急把 DNS 改回自动；`--restart always` 必开 |

## 决策口径

- 已有 NAS/软路由 → 直接用，不加硬件。
- 什么都没有 → 树莓派；不想加常驻设备 → 维持公共 DNS 现状（贴片保留）。
