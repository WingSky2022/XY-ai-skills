# scan-playbook · 两层扫描法

> 萃取自「双三角两层扫描方案」。适用：对被评者的多个项目做双三角六要素完备度 + Feature 思维判读。

## 0. 总原则

- **第一层（AI）**：判六要素「证据载体存不存在、全不全」→ 完备 / 部分 / 0 / 待确认。不判质量水平。
- **第二层（人）**：Gate 决断价值（审美锚点、创造力差异清单、场景 go/no-go）→ 见 `gate-cards.md`。
- 脚本管结构、AI 管语义、人管价值。

## 1. 扫描单元与批次

| 单元 | 判定 | 扫描方式 |
|---|---|---|
| 独立项目 | 有独立交付边界 | 逐条判读，六要素全画 |
| Skill 子模块 | 技能目录 | 只读 SKILL.md frontmatter，不读正文 |
| 项目簇 | 一个目录多个子项目 | 簇整体画布 + 待拆分清单，不擅自拆分登记 |

批次按证据价值切（P0 = 纳入核心画像且归属明确的资产优先逐条判读；P1 = 能力证据池；P2 = 归属未定者只画 AI 侧三要素；P3 = 仅索引级记录，全标低置信）。**条数以实际清单为准，不虚构。**

## 2. 六要素判据表（第一层）

分级：**完备** = 有明确文档/文件实证；**部分** = 有线索未深验/词面命中；**0** = 查证后确实没有；**待确认** = 证据不足或路径不可达。

| 要素 | 看什么 | 完备 | 部分 |
|---|---|---|---|
| 审美 | 质量标准载体：验收清单/评分规则/校验步骤/「好版本」参考 | 文档明确写出标准 | 词面含 质量校验/评分/审核 |
| 体系 | 三类说明文档 / SOP / 工作流定义 / 目录治理 | 齐全或成文 SOP | 有 1–2 类文档 |
| 创造力 | 差异化线索：独特设计/独有流程/反共识做法 | 文档明确记载 | 有垂直特色表述 |
| 基本功 | AI 特性运用：Agent/Skill 定义、prompt 工程、模型调用、工具编排 | 实测存在且含特性字段 | 仅字段有字样未实测 |
| 数据 | 知识库/语料/模板/案例库/数据管线 | 实测存在可指认数据 | 字段表明有未实测 |
| 场景 | 目标用户/应用域/价值线索 | 有定位且客户可理解 | 有域但无评估 |

铁律：**审美与创造力只判「标准/线索是否存在」，绝不判水平**（水平在 Gate 1/2）。

## 3. 三档扫描范围 × 要素支撑

| 档 | 说明 | 支撑 |
|---|---|---|
| (a) 元数据层 | 仅基于清单/索引字段初判，无需原始文件 | 体系/基本功/数据/场景中等；审美/创造力弱 |
| (b) 本地实测 | 读本地文件、frontmatter、git 历史 | 体系/基本功/数据强；创造力仍留 Gate |
| (c) 用户提供 | 原始目录导出/挂载 | 理论全覆盖；创造力仍留 Gate |

**路径可达性标注**（四值）：`本地已实测 / 仅元数据 / 路径不可达(跨机器源) / 待用户提供`。不可达一律 `待确认`，禁止写成 0；名称桥接须备注「未验证为同一实体」。

## 4. 置信档

| 档 | 条件 |
|---|---|
| 高 | 本地实测（文件/git/目录实测） |
| 中 | 多字段文档级 |
| 低 | 仅索引或词面命中 |

下游引用按置信档加权；汇总呈现时**高置信与低置信分列**，防「都扫过了」的虚假完备感。

## 5. Feature 思维判读维度（与六要素并行）

1. **候选 Feature 判物**：该产物是否「提升 AI 解题水平的最小实践单位」（四问：是否针对具体问题/是否可复用/是否可验证/是否长期稳定——工具速朽，Feature 长存）。
2. **周期律归位**：L1–L5 × 四维度（见 `feature-table.md`）；纪律「下层能解决就不上上层」。
3. **迭代证据**：git/版本史中的「假设 → 测试 → 改版」链；一假设一版可归因为最佳形态。
4. **沉淀阶段**：Library 六阶段（收藏/试用/验证/内核/边界/肌肉记忆）；**败因入账 = 「边界」阶段的标志性证据**。
5. **思维诊断**：工具思维（T 型，追工具）vs Feature 思维（F 型，攒方法）比例与拐点。

## 6. 执行方式自适应

- 多代理环境：按项目拆分并行扫描，主代理汇总审核（抽查关键声明、确认目标项目零改动）。
- 单代理环境：串行逐项目扫描，产物结构完全一致。
- 扫描全程**只读**目标项目；中间脚本为一次性文件，用后清理。
