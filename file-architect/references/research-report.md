## 一、六大主流体系总览

以下六个体系覆盖了当前最具代表性的文件与知识组织方法。它们的分歧在于“用什么作为第一分类维度”，而共识在于“减少决策成本、缩短查找路径”。

表 1　六大主流体系总览

| **体系** | **代表人物 / 来源** | **核心思想** | **适合场景** |
| --- | --- | --- | --- |
| PARA | Tiago Forte《Building a Second Brain》 | 按可操作性分四桶：Projects / Areas / Resources / Archives | 通用文件、笔记、项目的统一组织 |
| Johnny.Decimal | Johnny Noble | 全库编号：10 个 Area × 10 个 Category × 100 个 ID，最多两层 | 文件极多、需要精确“报坐标”找文件 |
| Kepano 极简库 | Steph Ango（Obsidian CEO） | 自底向上：文件夹极少，靠链接、属性与模板组织 | 笔记型知识库，反文件夹树 |
| Zettelkasten + MOC | 卢曼卡片盒法 / 中文社区实践 | 原子笔记 + 双链 + 内容地图（MOC）做索引 | 深度学习、研究、写作 |

## 二、各体系精华拆解

### 1. PARA：按“什么时候用”分类

PARA 的最大价值在于把分类依据从“这是什么”切换为“下次要用它时我会去哪找”。它按可操作性而非学科主题切分，因此天然适配“项目驱动”的工作方式。

* **Projects**：有截止日期、有明确产出的短期努力，如某客户交付、某次产品发布。
* **Areas**：无结束日期的持续责任，如销售流程、团队管理、健康管理。
* **Resources**：长期参考材料，如模板库、提示词库、方法论笔记。
* **Archives**：已完成或失效的内容，保留但不再占用注意力。

两条关键规则：活跃项目列表必须足够小（实践者通常收敛到 5 至 15 个真实项目）；项目结束时整文件夹移入归档且不改名，保证历史可搜索、路径可追踪。

### 2. AI 原生改造版 PARA

有团队在 50 余个项目中实践后，在 PARA 基础上增加了三个“系统前缀目录”，让 AI 不必询问就知道该往哪里写文件：

| 目录 | 职责 |
| --- | --- |
| `00_Inbox/` | 收集箱，每周清空，文件带日期后缀 |
| `01_Projects/` | 有时限的项目 |
| `02_Areas/` | 持续责任 |
| `03_Resources/` | 长期参考 |
| `04_Archive/` | 只进不改，可搜索不删除 |
| `05_Attachments/` | 二进制文件（PDF / 图片）集中存放 |
| `06_Metadata/` | 模板、规范、配置 |

配套铁律：

* **统一小写下划线**：路径永不带空格，AI 与脚本处理零转义问题。
* **每目录一个 README**：所有非叶子目录放说明文件，写明“这里放什么、当前状态”，AI 进目录先读它。
* **嵌套不超过三层**：再深即为“坏味道”，说明分类本身出错。
* **链接代替复制**：一份文件只有一个权威位置，别处引用而非复制。
* **活跃项目四件套**：每个在办项目只放概要、沟通日志、技术说明、进度四个文件，零歧义。

### 3. Johnny.Decimal：编号即坐标

Johnny.Decimal 用纯数字为全库建立坐标：每层最多 10 个选项、总共两层，编号形如 13.55。编号的稳定性解决了字母排序“新建即挤乱旧顺序”的顽疾，因而能形成真正的肌肉记忆，也可以直接在电话或会议中口头报出位置。

它在 AI 时代重新流行，原因有三：纯数字无歧义，AI 不需要理解“重要”“紧急”这类主观词；层级扁平，检索不会陷入嵌套地狱；一个编号即可作为文档属性中的单一字段。有实践者用 AI 工具整理七千余条笔记，采用渐进迁移策略：先只读扫描、再搭骨架索引、新文件强制带编号、旧文件摸到再改、每周十五分钟维护。

### 4. Kepano：反文件夹树的极简流

Obsidian 负责人 Steph Ango 公开的个人库采用“自底向上”思路：一级目录仅七个（附件、类别、剪藏、日记、笔记、参考、模板），导航主要依靠链接、属性与动态视图，而不是文件夹层级。同一篇笔记可以同时属于多个类别，索引由属性筛选自动生成。

其社区实践呈现两类典型模式：一类坚持一级扁平目录（如博客、运营、人物、指南、参考），另一类按时间流组织（年 → 周 → 日）。对项目型工作，常见做法是为每个项目维护两个文件——知识沉淀文件与计划文件。启示很明确：文档协作库适合文件夹树，思考型笔记库适合链接网，两者不应混用同一套逻辑。

### 5. 中文 Zettelkasten 实践

国内知识管理社区形成了高度稳定的编号前缀结构，把收集、加工、索引、项目、素材、归档串成一条流水线：

| 目录 | 阶段 |
| --- | --- |
| `00_Inbox` | 收集箱 |
| `01_文献笔记` | 文献摘录 |
| `02_Zettel` | 永久原子笔记 |
| `03_MOC` | 知识地图 |
| `04_Projects` | 项目 |
| `05_Resources` | 资源 |
| `06_Templates` | 模板 |
| `07_Assets` | 素材 |
| `08_Archive` | 归档 |
| `Home.md` | 总入口 |

社区共识的新手原则是：一级文件夹不超过八个、拒绝多层嵌套、附件统一存放不散落。命名上主张“主题优先、日期辅助”——正式笔记用语义化名称，日期只用于日志类笔记。这与本报告后面讨论的命名规范完全一致。

### 6. AI 原生知识库路由体系

与 AI 协作的知识库出现了新的一层：写给 AI 的导航文件。根目录维护一份主控文件，包含三段内容——目录索引、触发词路由表（把自然语言关键词映射到具体文件路径）、使用规则；每个一级目录再放一份本地说明，形成分层加载。

知识文件本身遵循“一个文件一个主题”，并带结构化元数据（标题、类别、标签、创建时间）。代码仓库侧的同类实践显示：主控文件只写指针与红线，可复用流程封装为独立技能文件，自动校验交给钩子，架构决策单独建档。有团队报告在大型代码库中应用后，AI 输出错误率下降约六成。其结论值得记住：仓库结构本身就是最根本的提示词。

### 7. 元数据命名法 / CPDX

国内影响较广的命名体系把文件名拆成七个元数据模块，按需组合：时间、前缀、标题、版本、标签、人物、备注。

```
(2024-03-01)-01-用户调研报告(v2)#已批准#北京@产品部
```

其中三条设计值得直接采纳：时间采用国际标准格式保证排序；版本号永远排在标题之后，使同项目不同版本自然相邻；标签与责任人用符号前缀标记，便于筛选与追溯。另一条被反复强调的纪律是——不要再用“最终版”“终极版”这类无法排序的表述。

## 三、高手们的最大公约数

把六套体系放在一起比较，会发现它们在“如何分类”上分歧明显，但在“如何降低查找成本”上高度一致。以下十条原则可直接复用：

1. **一级目录 7±2 个**，用编号前缀锁定排序，让位置形成肌肉记忆。
2. **嵌套不超过 3 层**，更深的层级意味着分类维度选错了。
3. **收集箱是唯一允许乱的地方**，并且每周强制清空。
4. **每个文件只有一个权威位置**，跨场景用引用而非副本。
5. **文件名 = 时间 + 主题 + 版本**，日期用国际标准格式，版本禁用“最终版”。
6. **归档只进不改**：项目结束当天整目录移走、不改名，历史始终可搜索。
7. **给 AI 写导航**：每个目录一份说明 + 根级触发词路由表，AI 开工先读索引。
8. **附件与文本分离**：二进制文件集中存放，不混在知识文件里。
9. **决策与教训单独建档**：这是 AI 长期记忆中最值钱的部分，避免重复踩坑。
10. **渐进迁移**：不追求 100% 合规，先保证高频文件与新文件合规，旧文件摸到再改。

## 四、与当前规范体系的对照

对照本工作区已有的四份规范文件，可以看出骨架与全球主流实践高度同构，差异只在于是否具备 AI 导航层与决策存档层。

表 2　现有规范与主流实践对照

| **当前规范** | **对应主流实践** | **可吸收的增量** |
| --- | --- | --- |
| 命名格式：日期\_项目\_描述\_版本 | 元数据命名法、CPDX | 多人协作时可选加标签与责任人后缀 |
| 编号目录树（项目 / 待整理 / 归档） | AI 原生 PARA、Johnny.Decimal | 骨架已一致，可为每个一级目录补说明文件 |
| 版本号递增 + 终稿唯一 | PARA 归档规则、CPDX | 已一致 |
| 每周清空待整理目录 | 收集箱每周清空 | 已一致 |
| 缺失：目录说明与路由表 | AI 原生知识库路由体系 | 建议增加索引与触发词路由，人与 AI 都能秒定位 |
| 缺失：决策记录 | 决策 / 教训归档实践 | 建议为规范变更、技术选型单独立档 |

> **结论**：当前体系骨架与全球高手实践同构，增量主要在“AI 导航层”与“决策存档”，实施成本极低，收益显著。
