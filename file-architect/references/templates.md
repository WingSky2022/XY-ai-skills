# 目录骨架与文件模板

按场景裁剪使用，**不要整份照抄**——一级目录超过 9 个就说明没做取舍。

## 一、默认骨架（AI 原生 PARA，项目驱动型工作区）

```
<工作区>/
├── CLAUDE.md 或 AGENTS.md      # 根级主控：目录索引 + 触发词路由 + 使用规则
├── 00_Inbox/                   # 收集箱：唯一允许乱的地方，每周清空
├── 01_Projects/                # 有时限、有明确产出的项目
│   └── <项目名>/               # 每个项目只放四件套
│       ├── README.md           # 项目概览与当前状态
│       ├── 概要.md
│       ├── 沟通日志.md
│       ├── 技术说明.md
│       └── 进度.md
├── 02_Areas/                   # 持续责任，无结束日期
├── 03_Resources/               # 长期参考：模板、方法论、提示词
├── 04_Archive/                 # 归档：只进不改，可搜索不删除
├── 05_Attachments/             # 二进制：PDF / 图片 / 音视频
├── 06_Metadata/                # 模板、规范、配置
│   └── Decisions/              # 决策存档：一条决策一个文件
└── 07_Logs/                    # （可选）日志类，按时间流组织
```

## 二、研究 / 学习型骨架（Zettelkasten + MOC）

```
<知识库>/
├── 00_Inbox/                   # 临时收集
├── 01_文献笔记/                # 读到的原始摘录，带来源
├── 02_永久笔记/                # 原子笔记：一个文件一个想法
├── 03_MOC/                     # 内容地图：手工维护的主题索引
├── 04_项目/                    # 有产出的写作/研究项目
├── 05_资源/                    # 长期参考
├── 06_模板/                    # 笔记模板
├── 07_附件/                    # 图片等
├── 08_归档/
└── Home.md                     # 总入口
```

## 三、极简笔记库骨架（Kepano 式，反文件夹树）

一级扁平，导航靠链接与属性，**不建深树**：

```
<笔记库>/
├── 附件/
├── 类别/
├── 剪藏/
├── 日记/
├── 笔记/
├── 参考/
└── 模板/
```

每篇笔记通过属性（`类别`、`状态`、`创建时间`）被视图自动聚合，同一篇可属于多个类别。

## 四、目录说明文件模板（每个非叶子目录一份）

```markdown
# <目录名>

## 这里放什么
<一句话说明本目录的职责边界>

## 不该放什么
<最容易误放进来的东西，以及它应该去哪>

## 结构
<若目录内还有子目录，在此列出并说明>

## 当前状态
<最后更新：YYYY-MM-DD>

## 给 AI 的提示
<AI 在本目录读写时需要注意的规则，没有就删掉本节>
```

## 五、根级主控文件模板（CLAUDE.md / AGENTS.md）

> 铁律：**只写指针与红线**。整份规范抄进来会让它随每次会话反复加载，臃肿即噪音。

```markdown
# <工作区名>

## 目录索引

| 目录 | 放什么 | 不该放什么 |
|:---|:---|:---|
| 00_Inbox/ | 未分类新文件 | 任何存活超过 7 天的文件 |
| 01_Projects/ | 有截止日期的项目 | 长期参考资料 |
| 02_Areas/ | 持续责任 | 一次性任务 |
| 03_Resources/ | 长期参考材料 | 活跃项目文档 |
| 04_Archive/ | 已结束的内容，只进不改 | 仍在编辑的文件 |
| 05_Attachments/ | PDF / 图片 / 音视频 | 任何文本文件 |
| 06_Metadata/ | 模板与规范 | 业务内容 |

## 触发词路由表

| 用户说到 | 去读 |
|:---|:---|
| 项目进度 / 交付节点 | 01_Projects/<项目名>/进度.md |
| 历史决策 / 为什么这么定 | 06_Metadata/Decisions/ |
| 命名规范 / 文件怎么放 | 06_Metadata/规范-文件架构.md |
| 模板 / 复用 | 03_Resources/ |

## 使用规则

- 写入任何目录前，先读该目录的 `README.md`
- 新文件一律先落 `00_Inbox/`，分类后归位
- 归档只进不改；需要改动时先取出、改完再重新归档
- 文件名格式：`YYYY-MM-DD_项目_描述_v{主}.{次}.{修}`
- 禁止使用「最终版 / 终极版」等不可排序的版本词
- 规范变更须在 `06_Metadata/Decisions/` 留档一条

## 红线

- 不在根目录堆放散落文件
- 不新建超过 3 层的目录
- 不复制已有文件，改用引用
```

## 六、决策记录模板（`06_Metadata/Decisions/`）

```markdown
# YYYY-MM-DD <决策标题>

## 背景
<为什么需要做这个决定，触发事件是什么>

## 选项
1. <方案 A> —— 优点 / 缺点
2. <方案 B> —— 优点 / 缺点

## 结论
<选定方案，以及关键理由>

## 影响
<谁会受影响，需要同步改什么>

## 复盘
<实施后回填：是否符合预期，若否，教训是什么>
```

## 七、项目四件套模板

| 文件 | 写什么 | 不写什么 |
|:---|:---|:---|
| `概要.md` | 目标、范围、成功标准、关键干系人 | 过程记录 |
| `沟通日志.md` | 按时间倒序的对外沟通要点与承诺 | 内部思考 |
| `技术说明.md` | 架构、关键选型、坑与绕过方案 | 进度流水 |
| `进度.md` | 当前状态、下一步、阻塞项 | 历史归档内容 |

## 八、命名规则判定速查

```
YYYY-MM-DD_项目_描述_v{主}.{次}.{修}[_状态][#标签][@责任人].{扩展名}
```

| 段 | 是否必填 | 说明 |
|:---|:---:|:---|
| `YYYY-MM-DD` | 必填 | 国际标准格式，保证跨系统排序正确 |
| `项目` | 必填 | 归属，用于同项目聚合 |
| `描述` | 必填 | 语义化内容名，不用缩写代号 |
| `v{主}.{次}.{修}` | 有版本时必填 | 紧跟标题，使不同版本自然相邻 |
| `_状态` | 可选 | `已批准` / `待评审` / `草稿` |
| `#标签` | 可选 | 便于筛选 |
| `@责任人` | 可选 | 多人协作时标注归属 |

**禁用**：空格、`最终版/终极版`、`2024.03.01` 式日期、`其他/杂项/临时` 类目录名。
