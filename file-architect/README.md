# file-architect

一个把「文件该怎么放」从口头约定变成可落地规范的 Agent 技能。

## 这是什么

文件架构的痛点不在于不知道该怎么分类，而在于每次都要重新决策一遍：这个文件放哪、叫什么名字、AI 怎么找到它。

`file-architect` 把六大主流文件架构体系的公约数固化成一套可执行流程。核心结论来自对这六个体系的横向调研——**高手们的结构高度趋同**：一级目录 7±2 个、嵌套不超三层、文件名承载时间与版本、收集箱定期清空、归档只进不改。差异只在「用什么作为第一分类维度」。

覆盖的六个体系：

| 体系 | 内核 |
|:---|:---|
| PARA | 按可操作性分四桶 |
| AI 原生 PARA | PARA + 系统前缀目录 + AI 导航层 |
| Johnny.Decimal | 编号即坐标，两层封顶 |
| Kepano 极简库 | 反文件夹树，靠链接与属性 |
| Zettelkasten + MOC | 原子笔记 + 双链 + 内容地图 |
| CPDX 元数据命名法 | 文件名即元数据 |

## 安装

把整个 `file-architect/` 目录放进你的 Agent 技能目录即可。无需任何依赖——审计脚本只用 Python 3 标准库。

```
file-architect/
├── SKILL.md                  # 主流程
├── scripts/audit_tree.py     # 目录体检脚本
└── references/
    ├── templates.md          # 骨架与模板
    └── research-report.md    # 六大体系调研报告
```

## 怎么激活

在对话里这样说话即可触发：

- 「帮我设计目录结构」
- 「文件命名怎么规范」
- 「给我建一套文件夹模板」
- 「知识库该怎么组织」
- 「我这个文件夹太乱了，帮我整理」
- 「整理文件架构」

## 它会交付什么

一次完整交付包含：

- **目录树** —— 按场景裁剪的骨架，含每层用途与「什么不该放这里」
- **命名规则 + 判定表** —— 可程序化判定的规则，而非「要清晰」这类空话
- **根级主控文件** —— 目录索引 + 触发词路由表 + 使用规则三段式
- **渐进迁移计划** —— 不要求一次性搬家，四阶段推进

## 附带脚本：目录体检

```bash
python3 scripts/audit_tree.py "<目标目录>"

# 调阈值 / 取机器可读结果
python3 scripts/audit_tree.py "<目录>" --max-depth 3 --inbox-age 7
python3 scripts/audit_tree.py "<目录>" --json
```

检测四类问题：嵌套超限、命名违规（含空格 / 「最终版」类版本词 / 非 ISO 日期）、收集箱堆积、目录说明缺失。**只读**，不移动或修改任何文件。

退出码：`0` 无问题，`1` 存在 WARN/ERROR，`2` 路径无效。

## 三条设计约定

1. **不做「一键重构目录」**。移动文件不可逆，涉及引用失效与历史断裂，必须逐步人工确认。脚本只做只读体检。
2. **模板不照抄**。SKILL.md 给了三套骨架（项目型 / 研究型 / 笔记型），按场景裁剪。一级目录超过 9 个即说明没做取舍。
3. **AI 导航层是核心增量**。多数规范缺失这一层。主控文件只写指针与红线，不抄整份规范——它会随每次会话反复加载，臃肿即噪音。

## 边界

- 只做架构设计与只读体检，**不替用户批量移动/改名文件**。
- 不判断某个具体文件「有没有价值」，那是人的判断。
- 单个文档的排版整理不属于本技能范围。
